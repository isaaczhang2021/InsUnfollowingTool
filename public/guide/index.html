使用手册

这份手册说明本仓库的完整用法：先在本地筛出要保留的账号，再把决定带进浏览器工具批量取关， 以及取关被 Instagram 限流时工具会怎么处理。

这是什么

项目由两部分组成，各管一段流程。

组成 运行在哪 做什么
浏览器工具 Instagram 页面的开发者控制台 扫描关注列表、标记白名单、批量取关
Following Seg.py 本地 Streamlit 离线逐个审阅、打标签，导出要保留的账号清单

所有数据只留在你自己的浏览器（localStorage）和本地文件里，没有服务端。 本工具与 Instagram 官方无任何关联，使用风险自负。

从哪里复制代码

只用本仓库的地址： isaaczhang2021.github.io/InsUnfollowingTool/

上游 davidarroyo1234 的页面不包含自动队列、节奏调试、批量白名单和失败冷却。 粘贴上游脚本后侧栏只有 Filter，没有 Progress 和 Pace，那就是复制错地方了。

  1. 在复制页点 Copy code
  2. 打开并登录 Instagram 网页版
  3. 打开控制台：Windows Ctrl + Shift + J，macOS ⌘ + ⌥ + I
  4. 粘贴回车，点 Run Scan

控制台里已经在跑的脚本不会热更新。每次合并 PR 并等 Pages 部署完成后， 都要回到复制页重新 Copy 一次，再开新一轮队列。

Android 可以装 Eruda 浏览器，用它打开 Instagram 网页版后同样能开控制台。

推荐工作流

关注量大的时候不建议在工具里逐个勾选。先在本地把「要留下的人」定下来，工具只负责执行剩下的取关。

  1. 在 Following Seg.py 里审阅，导出保留清单 whitelist_users.json
  2. 工具里打开 Settings → Whitelist → Import 选中该文件
  3. 回到 Non-Whitelisted 标签，按需要勾选筛选条件（例如只留 Non-Followers）
  4. 确认列表无误后点 Unfollow all matching

导入后这些账号会移到 Whitelisted 标签，从待取关列表里消失，任何模式下都不会被取关。 在扫描结果里多选账号后点 Whitelist selected 可以批量补充白名单， 在 Whitelisted 标签下则是 Remove from whitelist；点头像仍然是单个切换。

白名单、每页数量、单次取关上限、失败冷却时长都存在浏览器的 localStorage 里， 重新粘贴脚本后依然保留。换浏览器或清缓存前记得先 Export 一份白名单备份。

界面对照

扫描阶段（左侧栏）

控件 作用
Filter 勾选框 按 Non-Followers / Followers / Verified / Private / No Pic 过滤，同时决定自动队列会排进哪些账号
Per page 每页显示数量，下拉给 20 / 30 / 50 / 100 / 120，Settings 里可填 10–200 的任意值
Max unfollow this run 手动取关的单次上限，默认 20，可设 1–100
Select first N 按用户名排序取前 N 个替换当前勾选，N 就是上面那个上限
Unfollow (N) 取关已勾选账号，超出上限的部分会被跳过
Unfollow all matching 把当前筛选下的所有非白名单账号排成队列，一直跑到结束

容易混的一点： Max unfollow this run 只截断手动的 Unfollow (N) 和 Select first N。 Unfollow all matching 不受这个上限约束，几千个账号会全部进队列。

取关阶段（Unfollow Queue 侧栏）

显示项 含义
Progress 已处理数量 / 队列总数
Pace 当前生效的间隔：每个之间多久、每 5 个之后停多久
Last between / Last after5 上一次实际等待了多久，用来核对设置有没有吃进去
Est. left 按当前节奏估算的剩余时间
Status 手动暂停显示 Paused，失败冷却显示 Cooling down 加倒计时

右侧日志按时间顺序记录每次取关、每段等待和每次冷却。绿色是成功，红色是失败， 青色的 Waited 4.2s before next 是实际等待时长。

Settings（齿轮）

Settings 里的 time between unfollows 和 after five unfollows 只影响手动 Unfollow；自动队列用自己的自适应节奏。 Cooldown after 3 failed unfollows 则两种模式共用。

自动队列与节奏

队列起步是每个之间约 4 秒、每 5 个之后停 1 分钟，每次等待带 1.0–1.2 倍随机抖动， 所以日志里的数字总比设定值略大，属正常。连续成功 25 次会把两个间隔都乘 0.9 加速， 最快到 1 秒 / 10 秒；任何一次失败会把 between 乘 1.5、after5 乘 2 减速。

中途改节奏

  1. 点 Pause，等日志停止刷新
  2. 改 Between 和 After every 5（单位秒）
  3. 点 Apply pace，确认 Pace 那一行已经变成新值
  4. 点 Resume 继续

可设范围是 1–30 秒 和 10–600 秒，超出会被夹回边界， 此时 toast 会写明哪一项被 capped。没点 Apply 就 Resume，输入框里的数字不会生效—— 判断标准是看 Pace 那一行，不是看输入框。

新节奏从下一个账号开始生效，不会缩短已经开始的那次 after-5 等待。 另外自适应仍在运行，连续成功后间隔会自己慢慢变短。

失败与冷却

Instagram 在软限流时会照样返回 HTTP 200，但正文并不是成功。工具只把响应正文里 status: "ok" 认作成功，其余一律记为 Failed，并在控制台打出状态码和正文摘要。 所以日志里的 Unfollowed 是真的取关成功，不会出现「显示已取关、主页仍是 Following」。

连续 3 次 失败后队列自动进入冷却：

  • Status 变成 Cooling down 12:34 并逐秒倒数
  • 日志里留下一条冷却记录
  • 时间到了自动继续，并清零失败连击，不需要守在电脑前
  • 想提前继续就点 Resume，会跳过剩余时间

冷却时长默认 30 分钟，可在 Settings 或侧栏的 Cooldown after 3 failures 设成 5–180 分钟。侧栏改完点 Apply cooldown，对下一次冷却生效。 手动按下的 Pause 不属于冷却，不会自动恢复。

被限流时怎么办

连续大量 Failed 说明账号已经被限制动作。这时反复 Resume 只会延长限制时间。

  • 当天先停，隔 24 小时以上再试
  • 恢复后把冷却设到 60–90 分钟，节奏放到 between 15–30 秒、after5 180–300 秒
  • 与其一夜跑完几千个，不如每天限量几十个、分多天完成
  • 想确认是不是限流，在控制台 Network 里看 unfollow 请求的响应正文

间隔越短越容易触发风控。工具能做的只是识别失败并退让，无法绕过 Instagram 的限制。

开发与部署

  • Node 版本 16.14.0，用 nvm 的话执行 nvm use
  • npm run build 打包并把脚本嵌进 public/index.html
  • 推到 master 后 GitHub Actions 会把整个 public/ 发布到 Pages，本手册也在其中
  • 部署完成后必须重新 Copy 脚本，旧标签页里的版本不会变

手册是纯静态页面，不经过 webpack，直接改 public/guide/index.html 即可。
